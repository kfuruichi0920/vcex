# Web AI Bridge — Phase 0

Windows の VS Code Portable から、Edge 上の Web チャットに新しい質問を送り、回答を Markdown へ保存する拡張機能です。
現時点は **仮の React チャット専用**です。実際の LLM・外部サービスへは送信しません。

## 試す

開発リポジトリのルートで、検証用チャットを起動します。

```powershell
npm run mock:chat
```

別ターミナルで VSIX を作成します。

```powershell
npm run package --workspace=extensions/web-ai-bridge
```

VS Code Portable の拡張機能メニュー「VSIX からのインストール」で `web-ai-bridge-0.0.1.vsix` を選びます。
実行側は Windows、既存 Microsoft Edge、VS Code のみで動作します。Windows 標準 PowerShell をクリップボード操作に使用します。
Python・npm・別 Node.js・専用 Chromium のインストールは不要です。上記 npm コマンドは開発用と検証用チャットの起動用です。

ワークスペースを信頼して開き、設定で `webAiBridge.connectionMode` を `dedicated` にすると、CDP 未設定でも別プロファイルの Edge で試せます。
アクティビティバーの Web AI Bridge を開き、質問を入力 → 「送信前に確認」→「この内容で送信」と進めます。
最初に質問だけを試す場合はコンテキストを「なし」にしてください。
既存エディタからのコンテキストは初期状態で「自動」です。

## 接続設定

| 設定                           | 初期値・意味                                                                              |
| ------------------------------ | ----------------------------------------------------------------------------------------- |
| `webAiBridge.url`              | `http://127.0.0.1:4173`（検証用 React チャット）                                          |
| `webAiBridge.connectionMode`   | `cdp`。通常利用の Edge に接続。`dedicated` は別プロファイルで起動                         |
| `webAiBridge.cdpEndpoint`      | `http://127.0.0.1:9222`。Phase 0 はローカル HTTP のみ                                     |
| `webAiBridge.headless`         | `false`。専用 Edge のみ有効。**この環境では Headless のファイル Ctrl+V は受理されません** |
| `webAiBridge.profileDirectory` | 空欄は拡張機能の `globalStorage/edge-profile`。通常利用のプロファイルは指定しない         |
| `webAiBridge.logDirectory`     | 空欄はワークスペース内 `web-ai-bridge-logs`。保存先は送信前に表示                         |
| `webAiBridge.timeoutSeconds`   | 回答完了待ち 120 秒（仮値）                                                               |
| `webAiBridge.openLog`          | `true`。終了時にログを開く                                                                |

CDP は Edge のリモート操作用接続口です。通常の Edge を起動しただけでは接続できません。
組織で許可されたデバッグ構成の Edge を先に起動し、接続先を指定してください。
拡張機能は他の既存タブを操作せず、自分が作成したタブだけを閉じて切断します。既存 Edge を Headless へ変換することはできません。
専用 Edge は別の認証状態を持つため、将来の実サイトではログインが必要になる場合があります。

## コンテキスト・添付

- 自動: 最後にアクティブだったテキストエディタの選択範囲を付加。選択がなければ全文を実ファイルとして添付。
- 複数の選択範囲は文書内の順序で並べ、ファイル名・行番号を付けます。選択範囲には未保存の編集内容を含みます。
- 全文添付で未保存なら保存を確認します。無題・仮想ファイルの全文添付は中断します。
- 「ファイルを追加」で複数選択・個別削除できます。PNG はメモリ上で画像にして貼り付け、その他は Windows ファイルリストとして貼り付けます。
- D&D は元パスが得られないためファイル選択へ案内します。URL や画像を勝手に一時ファイル化しません。
- 実際に Ctrl+V を押し、全添付カードの完了・件数・ファイル名とサイズ（画像は MIME）を検証してから送信します。失敗しても別方式には切り替えません。
- 38,000 文字超は警告しますが送信できます。バイナリ容量は添付ごとに表示します。

クリップボード操作は専用 mutex で直列化し、元のデータを可能な範囲で退避・復元します。
全形式の完全復元は保証できません。貼り付け処理中に他アプリでコピー操作を行うと競合する場合があります。

## ログと中断

送信開始処理で `YYYYMMDD-HHMMSS_質問.md` を排他的に作成し、同名なら連番を付けます。
選択範囲と送信テキストを記録し、実ファイル添付の本文・バイナリ・絶対パスは記録しません。
接続先 URL の query/fragment、Cookie、認証情報は独自ログへ記録しません。
質問自体に含めた機密情報はログにも含まれます。

回答の明示完了シグナルを待ち、未完了回答は成功扱いしません。送信成否不明時は自動再送しません。
取消ボタン・`Web AI Bridge: 実行を取り消す` で中断できます。送信済みの質問は取り消せません。
ログを作成できない場合はブラウザ操作を開始しません。検証で弾いた入力や保存先が利用不可の場合はログを残せないことがあります。

## 今回の範囲と後続

Issue #1 の Phase 0 用に、サイドバー・コンテキスト・Edge 接続・実 Ctrl+V・回答取得・ログ保存を実装しています。
`/コマンド`、外部 Markdown 定型プロンプト、`@ファイル名` 補完、画像の直接貼り付け UI は後続フェーズです。
本物の Office/PDF の解析・各実サービスの形式制約や利用条件・実ログインは未検証です。
ライセンス・publisher は公開前に確定してください。

実サイト追加時は `src/adapter.ts` の `ChatAdapter` を実装し、`JobRunner` に渡します。
ログイン判定、新規チャット、添付完了、送信確認、回答完了・Markdown 化をその Adapter で実装します。
仮サイトの DOM がない URL に設定だけ変えても送信できません。

開発・検証の詳細はリポジトリの `docs/issue-1-phase-0.md` を参照してください。
